# ربط «ذاكرة عُمان الصوتية» بـ Supabase

الروايات تُحفظ في مشروع Supabase الخاص بالجمعية، والصفحات تعمل من GitHub Pages:

| الصفحة | الرابط في الموقع | لمن |
|---|---|---|
| الأرشيف ونموذج «شارك رواية» | `oral-history.html` | الجمهور |
| مراجعة الروايات | `oral-history-admin.html` | مشرفو الجمعية فقط (غير ظاهرة في القائمة) |

## كيف تُحمى البيانات

- **التسجيل الصوتي** يُرفع إلى حاوية خاصة (`oral-audio`) في مجلد انتظار، ولا يُسمع إلا بعد اعتماد الرواية.
- **الرواية** تُحفظ بحالة «بانتظار المراجعة»، ولا تظهر في الموقع حتى يعتمدها مشرف.
- **موافقة الراوي** (الاسم الكامل، العمر، المحافظة، الولاية، كل خيارات النشر، من أقرّ بالموافقة وصفته، ووسيلة التواصل) تُحفظ في جدول خاص `story_consents` لا يقرؤه إلا المشرفون.
- **ما يظهر للناس** يتبع اختيار الراوي:
  - إن لم يوافق على إظهار اسمه يظهر «راوٍ من …» ثم الولاية.
  - إن لم يوافق على إظهار عمره لا يُحفظ العمر في الجزء العام أصلاً.
  - إن لم يوافق على نشر النص المكتوب لا يُنشر.
- **لا تُحفظ رواية دون موافقتين:** موافقة الراوي على التسجيل، وموافقته على نشر صوته. والقاعدة نفسها تمنع الحفظ دونهما، حتى لو تجاوز أحد النموذج.
- **نسخة نص الموافقة** تُحفظ مع كل رواية (حالياً «1 · أكتوبر 2026»). إن عدّلت الجمعية نص الموافقة فغيّري `CONSENT_VERSION` في `src/archive-supabase.html`.

## خطوات الإعداد (مرة واحدة)

### 1) إنشاء الجداول والحاوية
- **إن كان ربط GitHub مفعّلاً في Supabase** مع خيار **Deploy to production**: يُطبَّق الملف `supabase/migrations/20261030000000_oral_history.sql` تلقائياً عند الدفع إلى الفرع `main`.
- **وإلا:** افتحي Supabase ← **SQL Editor** ← **New query**، والصقي محتوى الملف كاملاً، ثم **Run**. الملف آمن للتشغيل أكثر من مرة.

بعدها تأكدي من وجود:
- الجداول `stories` و`story_consents` و`admins` في **Table Editor**.
- الحاوية `oral-audio` في **Storage**، ويجب أن تكون **خاصة (Private)**.

### 2) ربط الموقع بالمشروع
- من **Project Settings ← API Keys** (أو زر **Connect**) انسخي:
  - **Project URL**، مثل `https://abcd1234.supabase.co`.
  - **Publishable key**، ويبدأ بـ `sb_publishable_`. يصلح أيضاً المفتاح القديم `anon`.
- ضعيهما في `docs/js/ohs-config.js`:

```js
window.OHS_SUPABASE = {
  url: "https://abcd1234.supabase.co",
  key: "sb_publishable_..."
};
```

هذا المفتاح مخصص للمتصفح وآمن للنشر في مستودع عام، لأن قواعد الصلاحيات في قاعدة البيانات هي التي تحمي البيانات. **لا تضعي أبداً المفتاح السري** (Secret key أو `service_role`) في أي ملف داخل المستودع.

### 3) إضافة مشرف
1. من **Authentication ← Users ← Add user** أنشئي حساباً للمشرف ببريد وكلمة مرور، وفعّلي **Auto Confirm User**.
2. ثم في **SQL Editor** شغّلي:

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'بريد-المشرف@example.com'
on conflict do nothing;
```

3. يدخل المشرف من `oral-history-admin.html`.

يُستحسن إيقاف التسجيل الذاتي للحسابات من **Authentication ← Sign In / Providers**، لأن المشرفين يُضافون يدوياً فقط.

### 4) تفعيل الموقع
- **Settings ← Pages** في GitHub، واختاري الفرع `main` والمجلد `/docs`.

## عمل المشرف

- **بانتظار المراجعة:** استمع للتسجيل واقرأ سجل الموافقة، ثم اعتمد ونشر، أو ارفض.
- **إلغاء النشر:** يعيد رواية معتمدة إلى «مرفوضة» فتختفي من الموقع.
- **الحذف النهائي:** يحذف الرواية وموافقتها وملف الصوت، ويحتاج ضغطتين للتأكيد. استخدميه إذا طلب الراوي أو أسرته حذف الرواية.

## ملاحظات

- **حجم الملف وصيغته:** أقصى حجم 25 ميجابايت، والصيغ المقبولة m4a وmp3 وwav وwebm وogg وaac. تسجيلات iPhone (m4a) وAndroid مقبولة.
- **ملفات يتيمة:** إذا رُفع ملف ولم يكتمل إرسال النموذج يبقى الملف في `pending/` دون رواية. يمكن حذف هذه الملفات من **Storage** دورياً.
- **نسخة Claude:** صفحة الأرشيف المنشورة داخل Claude تعمل بتخزين Claude الخاص، ولا تتصل بـ Supabase. النسخة الرسمية للجمهور هي نسخة GitHub Pages.
